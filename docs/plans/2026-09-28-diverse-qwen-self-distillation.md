# SciCode 自由出题与 Qwen 原生 trace：修订实施计划（待审核）

状态：历史计划。其后发现“科学问题”被实现成了纯概念问答，与 SciCode 科学编程 SFT 目标不符；当前实现与运行说明以 ../freeform_pipeline_v4.md 为准。分支 scicode-diverse-self-distill-v4 从 9fd494f7 创建，旧分支与旧数据保留。

## 目标与这次纠偏

核心目标仍是把 ScienceIDE 自动化造题流水线的思想用于 SciCode：让 Kimi 借助 SciCodePile 清洗后的科学代码素材自由造题，让基座 Qwen 以带随机性的采样生成自己的思维链和答案，最后用 Kimi 做适度的科学性、正确性审核，导出可用于 SFT 的原生 trace。Kimi 不充当默认 CoT 写作者。

回看 ScienceIDE/ScienceInfra：ScienceIDE README 指向 ScienceInfra 的任务工厂；LAPS 工厂在 demo/envs/laps/factory 中先批量构造候选，再通过 funnel 测量候选是否产生有效任务，PROBE.md 又通过实际模型试做分析难度。它的 lean-symptom 题面给出真实现象、目标及必要环境信息，把许多诊断留给解题者。这里借鉴的是**候选先充分生成、随后测量与筛选**，以及**从模型真实作答判断难度**。ScienceIDE 的容器构建、数值容差与题面中的工程操作说明服务于代码修复；SciCode 科学推理 SFT 不照搬这些细节。

上一版计划的问题是：用多维策略卡、固定类别和数量要求引导 Kimi，容易把自由造题变成填表；预审和多重检查可能将题目收缩成标准化模板；分层提示和额外的解题说明可能让 Qwen 形成统一、冗长的思考姿态。本版以更短的主流水线替代。

## 主流水线

SciCodePile 科学素材 → Kimi 自由出题（并留参考答案） → Qwen 随机采样原生 trace → Kimi 一次审核 → 格式核对与 SFT JSONL

每一步保存原始输出和生成参数。题目与 trace 可以多次采样；审核结果不覆盖原文。旧流水线及历史 JSONL 保持可读，新产物使用单独版本与目录。

### 1. 自由出题

沿用现有 SciCodePile 文件索引、候选抽取和批量任务队列。随机性首先来自不同科学素材与候选抽样，其次来自 Kimi 出题调用的随机采样参数；模型可以自行决定研究问题、背景和回答方式。作者提示词只交代目标——围绕给定科学素材提出有思考价值、可以判断科学对错的问题——并提供必要素材。现有三个 archetype 可以作为历史对照，首版新出题器以自由题目为默认路径。

机器存储只要求一个可解析的外壳：题面文本、来源标识、生成参数和内部参考答案。题目的科学情境、假设、数据及交付要求由 Kimi 按题意自然写入题面；不为这些内容设置固定清单、句式、字数或预定的推理动作数。若 Kimi 产生其他有用说明，可作为可选元数据保存。对重复与题型覆盖做批次统计，用统计反馈下一轮素材与采样选择，而不在单题写作阶段逐条塑形。

内部参考答案由 Kimi 给出，供后验核查；它与来源信息分开存放。Qwen 看到的仅是 Kimi 写出的题面及题目本身需要展示的背景或材料。渲染器原样传递这些内容，不再自动附加“列出假设、比较方法、解释科学方法”等统一尾句，也不把内部审查字段转成学生可见指令。Qwen 的系统消息采用模型部署所需的最简形式，避免固定的思考风格模板。

### 2. Qwen 随机采样原生 trace

以未经过本批 Kimi-CoT SFT 的基座 Qwen 为 solver。对同一题可多次独立采样，使用非零采样温度、可变化的 top_p 和每条 trace 独立的随机种子（以服务实际支持为准）；同时允许不同题目的题干自然变化。保存每次调用使用的实际参数、模型版本、题面哈希、原始响应、usage 和终止原因，并在 smoke 中检查重复采样是否真的产生了内容差异。采样轮数与参数分布在小规模试验中调整。

trace 使用 Qwen 原生返回的 reasoning_content 和 final content。中途截断、空答案或未返回 thinking 的响应仍进入原始归档并标记状态；训练视图只使用结构完整、内容经审查适用的响应。首版不设计分层提示或提示回合，也不由 Kimi 把参考答案拼接成一条看似 Qwen 的推理链。日后如确有需要，可把单次自然语言提示作为独立试验，而不是主流水线的条件。

### 3. 适度审核与格式保证

Kimi 在 Qwen 作答完成后做**一次综合审核**：题目是否有成立的科学语境，回答是否科学正确，推理是否能支持结论。审核者可借助相关源码、参考答案和题目材料，也可在适合的题上使用数值例子或运行结果作为辅助证据。审核输出一个结论、简要依据和不确定之处，不要求按“概念、假设、推导、实验、引用、交付”等固定项目逐项打分。困难、开放或多解的题根据实质论证判断。

程序只保证训练数据所需的格式和关联关系：JSONL 可解析，题面与 Qwen 实际输入一致，trace ID、模型、参数和来源可追溯，reasoning_content 与 final content 是对应的原生字段，审核结果对应同一题与同一条回答。这类检查负责数据正确拼接，不决定题目应该怎样思考。

所有题目与 trace 保存在原始层。科学正确、推理与答案相符且格式完整的 Qwen 响应进入 SFT 候选层；其他响应保留审核结论用于分析和再次采样。推理长度本身只做统计；重点观察是否有实质进展及最终答案是否完成。

### 4. SFT 导出与试验

导出行包含题目、Qwen 原生 reasoning_content、Qwen final content、必要的训练 loss 字段、采样参数、来源与审查信息。训练前用现有 Qwen 模板实际读取一个样本，确认 thinking 与 final 都按预期进入训练，而不是只在 JSONL 里存在。原始归档与 SFT 候选分开，后续可更换审核结论或训练配方而不重新造题。

先运行小规模端到端 smoke 并检查若干真实题干与 trace 的内容，再进行小规模训练对照。这是开发阶段的检查，批量生产仍使用自动审核。与基座 Qwen、旧 Kimi-CoT SFT 相比，重点看 SciCode 科学答题、最终答案完成率、冗长循环、原有能力回退，以及新题目的语义多样性和有效样本产率。根据这些结果决定下一轮采样、审核和扩量设置，不提前设定题型比例或推理长度硬指标。

## 预计代码改造顺序

1. 先改出题与学生可见渲染：factory/reasoning/prompts.py、author.py、schema.py、student_view.py。为新题建立轻量 schema，同时保持旧数据读取能力；测试题面原样进入 Qwen 请求。
2. 再改模型调用与 rollout：factory/reasoning/rollout.py、pipeline.py 及调用适配层。Kimi/Qwen 独立配置；随机采样参数、原生 thinking、终止状态与原始响应完整落盘；测试多次采样和续跑的身份一致性。
3. 收敛审核与导出：factory/reasoning/scientific_audit.py、grade.py、export.py 和相关数据转换。首版走单次 Kimi 综合审核与确定性格式校验；测试题目、回答、审查和 SFT 行的哈希与字段关联。
4. 最后接入现有 factory/reasoning/batch.py、queue.py 的并发与断点恢复，Kimi/Qwen 容量分别配置；先小规模 smoke，再根据实际产率进入批量。同步本地和 yicloud 新工作树，旧运行数据原封保留。

交付物：可审计的新任务 JSONL、Qwen 原生 trace JSONL、单次审核记录、SFT JSONL、格式验证报告，以及小规模题目/trace 内容和训练效果的对照报告。实施前以本计划接受用户审核为准。
